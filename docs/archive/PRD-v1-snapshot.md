# StepBuddy 小学数学步骤级智能诊断系统 PRD
## 一、产品概述
### 1.1 产品名称
小算星 —— 小学数学步骤级智能诊断系统

### 1.2 产品定位
面向小学1-6年级计算类数学题，基于「类编译器架构+规则引擎+大语言模型辅助」，实现**步骤级错误定位、知识点级原因归因、教学级思路讲解**的智能作业诊断工具。区别于传统「只判对错、只给答案」的拍照搜题产品，核心价值是「诊断解题过程，定位错误根源」。

### 1.3 产品愿景
让每一道数学题的订正都精准到「哪一步错、为什么错、怎么改正」，替代低效的重复刷题，实现基于知识漏洞的精准学习。

### 1.4 核心目标
1. **诊断精准性**：步骤级对错判定准确率≥95%，错误原因归因准确率≥90%；
2. **题型覆盖度**：覆盖小学1-6年级90%以上计算类题型（纯计算、列式计算、应用题、几何计算、解方程）；
3. **体验确定性**：同一道题多次诊断结果一致，核心判断无随机性；
4. **归因教学化**：错误解释符合小学教学逻辑，学生能看懂、家长能辅导、老师能参考。

## 二、用户与场景分析
### 2.1 目标用户
| 用户角色 | 核心特征 | 核心需求 |
|---|---|---|
| 小学生（1-6年级） | 自主订正作业，看不懂错题原因 | 知道哪步错、为什么错，有清晰的订正引导 |
| 家长 | 辅导孩子数学，自身不会讲/讲不专业 | 快速定位孩子知识漏洞，获得专业的讲解思路 |
| 小学数学教师 | 批改作业耗时，难以统计班级共性错题 | 批量批改作业，自动统计错题分布和知识点掌握情况 |

### 2.2 核心用户痛点
1. **学生端**：错题只打一个叉，不知道是审题错、列式错还是计算错；订正只抄答案，下次遇到同类题依然错；
2. **家长端**：能算出答案，但讲不清解题思路和错误原因；不知道孩子是粗心还是知识点没掌握，无法针对性辅导；
3. **教师端**：逐本批改作业占用大量时间；只能统计整题正确率，无法定位班级共性的步骤错误和知识漏洞。

### 2.3 核心使用场景
#### 场景1：学生自主订正作业
- 输入：拍照上传自己的解题过程，或手动输入题目+步骤；
- 过程：系统逐步骤诊断，标红错误步骤，展示错误原因和对应知识点；
- 输出：错误定位+原因讲解+正确解题路径+同类题推荐。

#### 场景2：家长辅导孩子作业
- 输入：拍照孩子的作业题和解题过程；
- 过程：系统输出诊断结果，同时提供家长辅导话术和知识点讲解；
- 输出：错题诊断+知识漏洞分析+辅导建议。

#### 场景3：教师批量批改作业
- 输入：上传全班作业照片，或批量导入学生答题数据；
- 过程：系统自动批改，统计每道题的正确率、错误步骤分布、知识点掌握率；
- 输出：批改结果+班级错题报告+知识点掌握分布图。

## 三、核心设计理念与整体架构
### 3.1 核心设计思路：类编译器的白盒诊断架构
借鉴编译原理的三层架构，将数学题的诊断过程拆解为「编译-生成-诊断」三个阶段，用确定性的规则引擎保证核心判断准确，用LLM解决自然语言的灵活性问题。

1. **前端编译层**：将自然语言题目、学生解题步骤，统一转换为标准化的结构化中间表示（IR）；
2. **中端规则层**：基于数学元规则库，针对题目生成所有合法解题路径的有向无环图（DAG），即「解题空间」；
3. **后端诊断层**：将学生步骤的IR序列与标准解题空间做匹配校验，定位错误步骤，匹配错误模式，输出归因结果。

### 3.2 整体技术架构
```
用户输入层 → 输入预处理模块 → LLM结构化转换 → 标准IR生成
                                      ↓
规则引擎层 → 元规则库 → 解题空间DAG生成 → 等价性校验引擎
                                      ↓
诊断输出层 → 步骤对齐 → 错误定位 → 错误模式匹配 → 归因生成
                                      ↓
用户端展示 → 学生端/家长端/教师端
                                      ↑
配置管理层 → 知识点体系配置、规则配置、评分标准配置
```

### 3.3 核心原则：规则为核，LLM为辅
严格划分规则引擎与LLM的权责边界，保证系统的确定性与可复现性：
- ✅ **规则引擎负责所有核心判断**：步骤对错判定、等价性校验、错误模式匹配、知识点归因；
- ✅ **LLM负责两端自然语言交互**：自然语言转结构化IR、诊断结果通俗化讲解、规则外场景兜底、同类题生成；
- ❌ **禁止LLM参与核心对错判定**，避免结果随机性。

## 四、核心功能模块详细设计
### 4.1 输入处理模块（前端编译层）
**核心目标**：将非结构化的自然语言输入，转换为标准化、无歧义的IR结构。

#### 4.1.1 题目输入与语义解析
- **支持输入方式**：拍照OCR、手动打字、截图识别；
- **题型自动分类**：自动识别纯计算、列式计算、应用题、几何计算、解方程、定义新运算6大类，匹配对应IR模板；
- **歧义消解机制**：
  1. 高歧义短语规则库前置校验：覆盖「增加了/增加到」「除/除以」「降价幅度」等经典歧义表述，直接锁定语义；
  2. LLM强制输出语义角色：每个数量关系标注「主体、基准量、比较量、运算关系」4个字段；
  3. 反向校验：生成IR后反向生成自然语言题干，与原题做语义相似度校验，低于0.9阈值触发二次解析。

#### 4.1.2 学生步骤归一化处理
- **原子步拆分**：LLM将学生原始步骤拆分为「单步单变换」的原子步序列，每一步仅对应一次数学变换（一次运算、一次变形、一次公式代入）；
- **非算式内容分类处理**：
  - 保留类：设未知数、单位、辅助线说明，纳入IR结构；
  - 过滤类：连接词、草稿计算，不进入规则引擎；
  - 规范类：解、答句格式，单独做答题规范校验。
- **多问题目拆解**：自动识别(1)(2)(3)小问，拆分为独立子题分别诊断，标注子问题间的依赖关系。

#### 4.1.3 OCR识别纠错
- **置信度分级处理**：高置信度字符直接使用，中置信度结合数学逻辑修正，低置信度标红提示用户确认；
- **常见识别错误映射**：内置×/x、6/0、b/6等常见混淆映射表，结合算式上下文自动修正；
- **修正标注**：所有自动修正结果标注「OCR修正」，支持用户手动修改，修改数据回流优化模型。

### 4.2 中间表示（IR）层
**核心目标**：定义统一的「数学中间语言」，是整个系统的交互基准。

#### 4.2.1 三级等价性定义
IR的等价判定分为三级，适配不同场景：
1. **严格数值等价**：左右两边数值完全相等，用于纯计算步骤校验；
2. **形式等价**：可通过合法元规则互推，用于解方程、恒等变形校验；
3. **近似等价**：误差在允许范围内，用于估算、保留小数场景。

#### 4.2.2 分层IR结构
采用三层语义结构，对应三层诊断能力：
| 层级 | 字段内容 | 诊断作用 |
|---|---|---|
| 实体层 | 已知条件、未知量、数值、单位、量纲类型 | 诊断漏看条件、抄错数、单位错误 |
| 关系层 | 数量关系谓词（和、差、倍、比、占等）、公式调用 | 诊断题意理解错误、公式记错、列式错误 |
| 表达式层 | 标准化算式、步骤序列、变换规则标签 | 诊断计算错误、规则误用 |

#### 4.2.3 扩展字段
- 约束字段：题目要求（简便运算、保留小数、方程解等）；
- 标签字段：每步变换对应的知识点、规则名称；
- 年级字段：对应学段的规则粒度要求。

### 4.3 规则引擎与解题空间生成模块（中端）
**核心目标**：基于元规则库，自动生成题目所有合法的解题路径，形成解题空间DAG。

#### 4.3.1 原子元规则库
按知识域分为三大类，按1-6年级分级形成白名单：
1. **运算定律类**：加法/乘法交换律、结合律、乘法分配律、减法性质、除法性质；
2. **数的性质类**：分数基本性质、比的基本性质、等式性质、商不变性质；
3. **操作类**：通分、约分、凑整、公式代入、单位换算、移项、合并同类项、系数化为1。

每条元规则采用「前提条件+变换模式+等价性证明」格式描述，确保数学严谨性。

#### 4.3.2 解题空间DAG生成
- **生成逻辑**：从题目初始表达式出发，应用所有适用的元规则，生成下一步表达式节点，循环迭代直到得到最终结果；
- **剪枝策略**：
  1. 等价节点合并：数值和结构均等价的节点合并，避免重复；
  2. 深度限制：根据题目复杂度设置最大步骤数，超过停止扩展；
  3. 教学合理性剪枝：剪掉明显绕路、不符合小学解题逻辑的路径。
- **路径优先级**：所有合法路径对错判定平等；教学推荐路径按简便性、课标要求排序。

#### 4.3.3 特殊规则适配
- **跳步判定规则**：按年级配置「最大允许合并规则数」，只要步骤间严格等价且合并规则数在范围内，即为合理跳步，不判错仅提示；
- **超纲规则处理**：超出年级知识点白名单的规则，步骤正确但标注「使用高年级知识点」；
- **定义新运算**：LLM从题目提取规则，动态注入引擎，临时生效。

### 4.4 智能诊断模块（后端）
**核心目标**：精准定位错误步骤，匹配错误模式，输出分层归因。

#### 4.4.1 错误定位：反向溯源法
1. 从学生最后一步往前，逐次与标准解题DAG做等价性校验；
2. 找到第一个与标准路径不等价的步骤，标记为**源头错误步**；
3. 后续步骤标注「基于前序错误结果，推导逻辑正确」，不重复扣分。

#### 4.4.2 三级错误定位颗粒度
1. **步骤级**：定位到第几步出错；
2. **规则级**：定位到违反哪条元规则、对应哪个知识点；
3. **位置级**：定位到步骤中具体出错位置（如分配律漏乘第二项）。

#### 4.4.3 错误模式匹配与归因
采用三级错误模式库，匹配后输出标准化归因：
| 错误大类 | 子类 | 归因输出示例 |
|---|---|---|
| 知识性错误 | 概念误解、规则误用、公式记错 | 「错误原因：异分母分数加减法未通分，未理解分数单位相同才能相加减」 |
| 行为性错误 | 抄错数、计算失误、笔误 | 「疑似笔误：3×7正确结果为21，建议检查乘法口诀」 |
| 规范性错误 | 格式错误、漏写单位、没写答句 | 「答题规范：计算结果后需加上单位‘个’」 |

#### 4.4.4 多错误与连锁错误处理
- **优先级排序**：审题错误 > 列式/公式错误 > 计算错误 > 答题规范错误，优先反馈核心错误；
- **连锁错误剥离**：仅源头错误扣分，后续推导正确不扣分，避免重复惩罚；
- **笔误与知识错误区分**：单题中单个数字接近错误判定为疑似笔误；同一学生多次同类错误判定为知识漏洞。

#### 4.4.5 分步评分
- 标准解题DAG的每个节点配置评分权重，列式、计算、格式分别占比；
- 支持配置不同评分标准（考试模式/练习模式）；
- 输出总分+步骤分项得分。

### 4.5 LLM能力适配层
**核心目标**：严格限定LLM能力边界，保证输出可控、准确。

#### 4.5.1 LLM权责边界
| 允许LLM做 | 禁止LLM做 |
|---|---|
| 自然语言题目/步骤转结构化IR | 步骤对错判定 |
| 诊断结果通俗化润色 | 错误原因定性 |
| 规则外场景兜底诊断 | 知识点掌握度评估 |
| 生成同类练习题 | 生成新的数学规则 |

#### 4.5.2 输出一致性保障
1. **强制Schema**：所有结构化输出严格遵循定义好的JSON格式，字段、表达式写法统一；
2. **Few-shot示例**：每个任务配3-5个高质量示例，统一输出风格；
3. **输出校验器**：格式校验+数学合理性校验，不通过自动重试，最多3次。

#### 4.5.3 兜底机制
- 触发条件：规则引擎无法匹配、题型超出覆盖范围；
- 输出要求：兜底结果明确标注「本题为特殊题型，诊断结果由AI生成，仅供参考」；
- 闭环迭代：兜底结果进入人工审核池，定期沉淀为新的元规则和错误模式。

### 4.6 用户端功能模块
#### 4.6.1 学生端
1. **拍照诊断**：拍照上传题目+解题过程，一键获取诊断结果；
2. **分层反馈**：
   - 第一层：整题对错+错误步骤标红；
   - 第二层：点击错误步骤，展示错误原因、对应知识点；
   - 第三层：查看完整正确解题步骤和思路讲解；
3. **错题本**：自动收录错题，按知识点分类，支持导出打印；
4. **同类题练习**：基于错误知识点推送同类练习题，巩固强化。

#### 4.6.2 家长端
1. **诊断结果同步**：同步孩子的错题诊断结果；
2. **知识漏洞报告**：按周/月生成孩子的知识点掌握报告，标注薄弱点；
3. **辅导话术参考**：每道错题提供家长辅导话术，降低辅导门槛；
4. **学习建议**：基于薄弱点给出针对性学习规划。

#### 4.6.3 教师端
1. **批量批改**：上传班级作业照片，自动完成批改，输出批改结果；
2. **班级错题统计**：每道题的正确率、高频错误步骤分布；
3. **知识点掌握分析**：班级整体知识点掌握率、共性薄弱点；
4. **作业讲评素材**：自动生成错题讲评PPT，包含高频错误、正确解法、知识点总结。

### 4.7 后台配置管理模块
1. **知识点体系配置**：支持按课标、教材版本调整知识点分级；
2. **元规则配置**：支持新增、修改元规则，调整规则年级归属；
3. **错误模式配置**：支持新增错误模式、编辑归因话术；
4. **评分标准配置**：支持自定义步骤分值、规范扣分标准；
5. **教材版本适配**：内置人教版、苏教版、北师大版默认配置，支持一键切换。

## 五、知识库体系设计
### 5.1 知识点体系
- 遵循义务教育数学课程标准，按「学段→年级→单元→知识点→子知识点」五级划分；
- 每个知识点绑定对应元规则、错误模式、讲解模板；
- 支持不同教材版本的知识点顺序调整。

### 5.2 元规则库
- 冷启动阶段：由一线小学数学专家梳理1-6年级核心计算元规则共86条，覆盖全部主流运算；
- 迭代机制：定期从兜底场景、用户反馈中沉淀新规则。

### 5.3 错误模式库
- 冷启动阶段：专家梳理Top 120高频错误模式，覆盖90%以上学生常见错题；
- 每条模式包含：错误特征、匹配规则、对应知识点、错误本质、讲解话术；
- 迭代机制：基于用户答题数据和纠正反馈，持续挖掘补充低频错误模式。

## 六、非功能需求
### 6.1 性能需求
- 单题诊断响应时间：≤1秒（常规计算题），≤2秒（复杂应用题）；
- 解题空间生成时间：单题≤500ms；
- 批量批改：50份作业单题批改≤30秒。

### 6.2 准确率需求
- 步骤级对错判定准确率：≥95%；
- 错误原因归因准确率：≥90%（与专家标注对比）；
- LLM结构化转换准确率：≥98%。

### 6.3 兼容性需求
- 支持微信小程序、H5、APP多端访问；
- 支持主流教材版本（人教版、苏教版、北师大版）；
- 支持不同年级的规则粒度自适应。

### 6.4 安全性与合规性
- 学生数据加密存储，符合《个人信息保护法》；
- 不收集未成年人敏感信息；
- 所有AI生成内容符合教育导向，无错误知识引导。

## 七、迭代规划
### 7.1 P0阶段：核心引擎验证版（1-2个月）
**目标**：验证编译器架构的可行性，跑通核心诊断流程
- 覆盖范围：4-6年级整数、小数、分数四则混合运算+简便运算+解方程；
- 核心功能：基础IR结构、核心元规则库（40条）、基础错误模式库（60个）、反向溯源诊断、拍照输入+手动输入；
- 交付标准：步骤级准确率≥90%，单题响应≤1.5秒。

### 7.2 P1阶段：全题型覆盖版（3-4个月）
**目标**：覆盖小学全年级计算类题型，完善诊断深度
- 覆盖范围：1-6年级全计算类题型，新增应用题、几何计算、列式计算；
- 核心功能：三层IR结构、完整元规则库（86条）、完整错误模式库（120个）、应用题语义解析、几何公式校验、分步评分、错题本；
- 交付标准：题型覆盖率≥90%，归因准确率≥90%。

### 7.3 P2阶段：体验与运营优化版（5-6个月）
**目标**：完善多角色功能，提升产品体验，建立运营闭环
- 核心功能：家长端知识报告、教师端批量批改+班级统计、同类题生成、答题规范配置、多教材版本适配；
- 性能优化：缓存体系优化、OCR纠错模型迭代；
- 交付标准：用户诊断满意度≥85%，支持千人级并发。

## 八、风险与应对策略
### 8.1 技术风险
1. **风险**：LLM结构化输出不稳定，导致IR生成错误
  - 应对：强制Schema+输出校验器+反向校验三重保障，核心字段硬编码校验规则。
2. **风险**：解题空间组合爆炸，性能不达标
  - 应对：三层剪枝策略+常见题型预缓存，小学计算题复杂度低，实际路径数可控。
3. **风险**：特殊题型、偏题规则覆盖不全
  - 应对：LLM兜底机制+人工审核闭环，逐步沉淀规则，缩小兜底范围。

### 8.2 产品风险
1. **风险**：诊断结果不符合老师教学要求，不被认可
  - 应对：课标为基准制定规则，邀请一线教研专家审核，支持学校自定义规则配置。
2. **风险**：用户误以为系统能“读心”，预期过高
  - 应对：产品文案统一使用「步骤级诊断」表述，明确诊断的是解题逻辑，不做过度承诺。

### 8.3 运营风险
1. **风险**：冷启动阶段错误模式不全，准确率不足
  - 应对：专家前置梳理高频错误，上线后收集用户反馈快速迭代，前3个月重点优化准确率。
2. **风险**：教材版本多，适配成本高
  - 应对：核心规则统一，知识点顺序和术语配置化，新增版本仅更新配置表。
