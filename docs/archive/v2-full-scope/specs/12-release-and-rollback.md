# 12 发布、灰度与回滚

## 本文档解决什么问题

规则库与错误模式库是这个产品的核心资产，也是变更最频繁的部分。前十一份文档详细规定了「规则怎么定义」「结果怎么判定」，却没有规定「新规则怎么上线」。全库检索灰度与回滚，零命中。

缺这一章的后果很具体：改一条元规则可能让一万道历史题的结论变化，而没有任何机制能发现、限制或回退。诊断快照能回放，但**回放之后怎么回滚、回滚后旧结果怎么处理，没人定义**。

本文档定义版本规则、灰度、回滚与变更门禁。运行时自动降级（预算、QPS 触发）不属本文档，见 [07-performance-and-cost.md](./07-performance-and-cost.md) §5。

## 前置依赖与文档关系

回归门禁依据 [04-eval-set-and-annotation.md](./04-eval-set-and-annotation.md) §8.3；快照与版本四元组见 [08-diagnosis-result-schema.md](./08-diagnosis-result-schema.md) §2、§6；工程顺序见 [10-assumptions-and-limits.md](./10-assumptions-and-limits.md) §4。

## 1. 产品版本号规则

| 版本位 | 递增条件 | 示例 |
|---|---|---|
| 主版本 | 覆盖范围变更（新增或移除题型族）、诊断算法方向性变更 | 1.0 → 2.0 |
| 次版本 | 新增规则族、新增用户端功能、接口新增字段 | 1.0 → 1.1 |
| 修订号 | 规则修正、错误模式补充、文案调整 | 1.1 → 1.1.1 |

**规则库版本独立编号**，格式 `R-<主>.<次>.<修订>`，与产品版本号解耦——规则库每天可能变，产品版本不会。每个诊断结果记录规则库版本（`08` §2）。

PRD 文档版本（当前 v2.0）与产品版本号是两套编号，不得混用。产品首次对外发布对应 1.0 的时点由 PRD §7.x 阶段决定。

## 2. 发布节奏与阶段滚动

| 类型 | 节奏 | 说明 |
|---|---|---|
| 规则库修订 | 按周或按批 | 每批须跑全量回归 |
| 错误模式库 | 同上 | 同上 |
| 结构化提示词 | 变更即视为破坏性变更 | 触发全量回归 + 一致性子集复测 |
| 模型版本 | 锁定，变更需评估 | 见 `04` §8.2 |
| 产品版本 | 按阶段 | P0/P1/P2 |

**P0 期间的变更窗口**：P0 阶段规则库处于快速增补期，允许每日发布，但每次发布必须跑回归子集（P0 子集 1200 题）。回归通过率低于基线 2 个百分点即阻断（`04` §8.3）。

**阶段切换时的优先级重排**：进入 P1 时须重新评估 P1 范围与优先级。若 P0 的某题型族实测准确率明显低于阈值，不得带着问题进入 P1，应先收窄范围或补规则。

## 3. 灰度策略

灰度对象分四类，各有不同的灰度维度。

| 对象 | 灰度维度 | 初始放量 | 观察指标 | 全量条件 |
|---|---|---|---|---|
| 新规则族 | 按题型族（只影响相关题） | 5% 相关题 | 该题型的步骤级判定准确率、排除项占比 | 48 小时内不低于基线 |
| 规则修正 | 按题型族 | 10% | 同上 + 回归通过率 | 24 小时内无异常 |
| 结构化提示词变更 | 按题（全题型） | 5% | M-3a/b/c 三项、退化率 | 24 小时内三项不低于基线 |
| 讲解生成变更 | 按题 | 10% | 讲解归因可追溯率、可读性与家长可理解度抽样 | 48 小时内无退回 |

灰度期间的**失败判定**：任一观察指标跌破基线超过 2 个百分点，立即回滚该批次。

**解释生成不做灰度到讲解质量的主观判断**——主观质量靠 `04` §7 的抽样评估，不靠灰度数据。灰度的价值在于发现结构性退化（可追溯率下降、排除项激增）。

## 4. 回滚

### 4.1 规则库回滚

| 项 | 规则 |
|---|---|
| 回滚粒度 | 按发布批次，不按单条规则 |
| 回滚耗时目标 | 一个发布周期内完成（具体分钟数待部署形态确定） |
| 回滚后 | 触发一次回归子集复跑，确认恢复到基线 |
| 回滚记录 | 记入发布历史，含回滚原因、影响题量、责任人 |

### 4.2 诊断结果回滚的边界

这是容易出错的地方。规则库回滚后，**历史诊断结果不自动重算**：

| 情形 | 处理 |
|---|---|
| 用户主动查看历史结果 | 展示「本结果基于版本 X，可重新诊断」提示（界面五态规范的数据过期态，见 `11` §3） |
| 用户主动重新诊断 | 产生新结果，原结果保留不覆盖 |
| 掌握度模型消费 | 以产生该结果时的规则版本为准，不得用新规则重算历史证据（`05` §3） |
| 争议复核 | 以诊断快照为准，快照含版本四元组，可精确复现当时的判定 |

**不得批量重算历史结果**。重算会让家长看到「昨天的结论今天变了」，且掌握度证据的时间序列会被污染。

### 4.3 快照回放

快照（`08` §6）是复现的唯一依据。回放条件：四项版本齐备且快照在保留期内（12 个月）。版本不齐备时回放结果仅供参考，不作为质量判定依据。

## 5. 变更门禁

| 变更类型 | 门禁 | 审批 |
|---|---|---|
| 新增规则 | 附验收用例编号（否则阻断） | 单人可审（当前无团队） |
| 规则修正 | 回归子集通过 | 单人可审 |
| 规则库发布 | 全量回归通过 | 单人可审 |
| 提示词变更 | 全量回归 + 一致性子集 | 单人可审 |
| IR schema 破坏性变更 | 提供升级器 + 全量回归 | 需记录影响面 |
| 模型版本变更 | 全量回归 + 基线压测复跑 | 需记录影响面 |

**「单人可审」是当前无团队的现实**。门禁的价值在于强制跑回归与留痕，不在于多人复核。团队扩充后应改为双人。

## 6. 发布检查清单

每次规则库或提示词发布前逐项确认：

- [ ] 变更内容与影响题型族已记录
- [ ] 新增或修改的规则均附验收用例编号
- [ ] 全量回归已通过，无指标跌破基线
- [ ] 一致性子集复测通过（规则层 100%）
- [ ] 灰度计划已设定放量比例与观察指标
- [ ] 回滚方案已准备（上一版本可一键回退）
- [ ] 发布历史已记录（时间、内容、责任人、批次号）
