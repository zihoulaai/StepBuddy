# 13 外部依赖、韧性与可维护性

## 本文档解决什么问题

前十二份文档把「怎么诊断」写得很细，但系统要跑起来还依赖三样外部东西：识别服务、结构化模型、模型网关。这三个依赖的契约、不可用时的产品表现、供应商怎么换，全库没有定义。`07` §5 定义了七个降级开关，但降级后产品变成什么样，没有产品口径。

同时，可维护性（规则库怎么改、schema 兼容多久）、灾备（数据丢了怎么办）、安全工程措施（`06` 只有隐私合规条款，没有工程措施）、审计日志（`06` §6.3 要求留痕但无规格）四处全缺。

本文档补齐这五块。

## 前置依赖与文档关系

降级开关行为见 [07-performance-and-cost.md](./07-performance-and-cost.md) §5；隐私合规条款见 [06-identity-and-data-model.md](./06-identity-and-data-model.md) §5；灰度回滚见 [12-release-and-rollback.md](./12-release-and-rollback.md)；发布门禁见 `12` §5。

## 1. 外部依赖清单

| 编号 | 依赖 | 用途 | 数据是否出域 | 不可用时的产品表现 |
|---|---|---|---|---|
| D-1 | 识别服务（OCR） | 图片转文本与算式 | 是，图片与文本 | 降级 G-3：转手输；保留原图与识别结果对照 |
| D-2 | 结构化模型 | 题目解析、原子步拆分、IR 生成 | 是，仅表达式与步骤文本（C-7 限制） | 重试 3 次后转手输；不进入规则引擎 |
| D-3 | 讲解模型 | 讲解文本生成 | 是，仅结构化后的表达式与判定结论 | 降级 G-2：模板文案，标注「标准讲解稍后补充」 |
| D-4 | 模型网关/供应商 | 承载 D-2、D-3 调用 | 同 D-2、D-3 | 按 G-2/G-3 降级；周期预算耗尽时 G-5 |

### 1.1 依赖契约要求

每项依赖必须明确四件事，缺一不可：

1. **数据边界**：传出哪些字段，禁止哪些字段（姓名、学校、班级、照片一律禁止，见 `06` §5 C-7）；
2. **可用性目标**：目标值**待选型后确定**，当前不得写具体数字；
3. **超时与重试**：与 `09` §8 的重试规则一致；
4. **降级责任**：由谁判定不可用、降级后如何恢复、恢复是否自动。

### 1.2 供应商切换预案

| 项 | 要求 |
|---|---|
| 抽象层级 | 依赖通过适配层接入，业务层不直接依赖供应商接口 |
| 切换成本 | 切换须重跑全量回归（不同供应商的结构化输出风格不同，M-3 会变） |
| 切换触发 | 成本超预算（`07` §4）、可用性不达标、合规要求 |
| 禁止事项 | 不得在业务代码中硬编码供应商专有字段 |

## 2. 备份与灾备

| 项 | 要求 | 状态 |
|---|---|---|
| 数据分类 | 结构化数据（账号、诊断记录、掌握度）与非结构化数据（作业照片、快照）分开备份 | — |
| 备份周期 | **待部署形态确定后回填** | 占位 |
| RPO（恢复点目标） | **待定**，建议结构化数据 ≤1 小时，非结构化数据 ≤24 小时 | 占位 |
| RTO（恢复时间目标） | **待定** | 占位 |
| 恢复演练 | 每季度一次，演练结果留档 | — |
| 删除的不可恢复性 | 用户请求删除后不可恢复（`06` §5 C-6），备份中的同一数据须同步清除 | — |

**备份中的删除联动**是最容易漏的一条：若备份副本未同步清除，用户的删除请求在法律意义上未完成。这一条必须写进 `06` §5 C-6 的执行细则。

## 3. 可维护性

### 3.1 规则库与错误模式库

| 项 | 要求 |
|---|---|
| 变更方式 | 通过后台配置管理，不通过代码发布（PRD 4.7） |
| 变更审批 | 见 `12` §5 门禁 |
| 版本化 | 每次变更生成新版本号，可回退到上一版本 |
| 热更新对进行中诊断的影响 | **进行中的诊断使用发起时的规则版本，不得中途切换**；切换只影响新发起的诊断 |
| 回归门禁执行人 | 当前为单人，见 `12` §5 说明 |

### 3.2 IR schema 与结果 schema 兼容

| 变更类型 | 兼容要求 |
|---|---|
| 新增可选字段 | 向后兼容，读取方须容忍缺失 |
| 新增必填字段或改语义 | 破坏性变更，须提供升级器；升级失败时该记录降级为只读 |
| 兼容窗口 | **待定**，建议不少于 6 个月（与 `08` §6 快照保留期 12 个月协调） |

### 3.3 代码与文档的一致性

| 项 | 要求 |
|---|---|
| 规格文档为唯一事实来源 | 实现与文档冲突时以文档为准并修正实现，不得反向改文档迁就实现 |
| 文档随变更更新 | 规则或 schema 变更须同步更新对应 spec |
| 追踪矩阵回填 | 每次变更回填 `00` §4 的对应行 |

## 4. 安全工程措施

`06` §5 是隐私合规条款，本节是工程措施，两者不重复。

| 编号 | 措施 | 要求 |
|---|---|---|
| S-1 | 上传内容安全扫描 | 作业照片须做内容安全扫描，命中违规内容的上传拒绝并记录 |
| S-2 | 接口鉴权 | 所有接口须鉴权；越权访问返回 `E-AUTH-DENIED` 且不泄露资源是否存在（`09` §7.2） |
| S-3 | 防重放与防刷 | 请求须防重放；诊断接口按用户配额限流 |
| S-4 | 密钥管理 | 第三方服务密钥集中管理，不进代码库；支持轮换 |
| S-5 | 传输与存储加密 | 传输加密；存储加密范围与 `06` §5 一致 |
| S-6 | 渗透测试 | 每个产品主版本发布前完成一次安全评审；当前无团队，可先做自查清单 |
| S-7 | 依赖漏洞 | 第三方依赖定期更新，高危漏洞须在**待定**时限内修复 |

## 5. 审计日志

`06` §6.3 要求管理员访问个案「操作全程留痕」，本节给出规格。

| 字段 | 说明 |
|---|---|
| `actor_id` | 操作者 |
| `action` | 操作类型（查看、导出、修改、删除、授权、撤销授权） |
| `target_type` / `target_id` | 操作对象（学生、诊断记录、班级、规则） |
| `reason` | 操作事由（临时授权场景必填） |
| `timestamp` | 时间 |
| `source` | 来源（端类型、地址信息，具体字段待合规确认） |

| 项 | 要求 |
|---|---|
| 留存期 | **待定**，建议不少于 12 个月 |
| 不可篡改 | 审计日志只追加，不提供修改与删除接口 |
| 可查范围 | 管理员可见全部；教师仅可见本人对本人班级的操作；家长与学生不可见 |
| 关联 | 临时授权（`06` §6.3）的每次数据访问均须产生审计条目 |

## 6. 监控与告警的补充

`07` §6.2 已定义监控指标与告警阈值，本节只补两类：

| 类别 | 监控项 | 告警 |
|---|---|---|
| 依赖健康 | D-1 至 D-4 的可用性与延迟 | 可用性低于目标或延迟超阈值持续 5 分钟 |
| 发布健康 | 灰度批次的观察指标（见 `12` §3） | 跌破基线 2 个百分点 |
