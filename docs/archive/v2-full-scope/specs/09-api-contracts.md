# 09 接口契约

## 本文档解决什么问题

PRD 6.3 写「各端共用同一诊断接口，端侧不实现业务规则」，但全库没有任何接口定义——「诊断接口」到底指后端服务、客户端 SDK 还是 HTTP API，三处读法都能成立（G-33）。前端无法开工，后端无法定边界，批量批改的续跑语义也没有承载点。

本文档定义逻辑接口契约与统一错误码。传输协议、序列化方式、鉴权实现细节留待技术选型，选型不改变本文档定义的载荷与错误语义。

## 前置依赖与文档关系

载荷引用 [08-diagnosis-result-schema.md](./08-diagnosis-result-schema.md) 与 [01-ir-schema.md](./01-ir-schema.md)；退出码语义来自 [03-alignment-and-diagnosis.md](./03-alignment-and-diagnosis.md) §8.1；字段级可见性受 [06-identity-and-data-model.md](./06-identity-and-data-model.md) §3 约束；异常流程与续跑的用户侧行为见 [11-interaction-flows.md](./11-interaction-flows.md)。

## 1. 术语指代

| 本文用词 | 含义 |
|---|---|
| 诊断接口 | 后端诊断服务对外提供的能力入口，端侧通过它提交题目与步骤、取回诊断结果 |
| 载荷 | 请求与响应的数据结构，与传输协议无关 |
| 端侧 | 小程序、H5、App 三种客户端，共用同一套载荷 |

本文档定义的是**载荷与语义**，不是传输层。

## 3. IF-1 提交诊断

### 3.1 请求

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `student_id` | string | 是 | 归属学生 |
| `input_type` | enum | 是 | `photo` / `manual` / `screenshot` |
| `image_ref` | string | 否 | `input_type=photo` 时必填，图片存储引用 |
| `question_text` | string | 否 | 手输题目文本 |
| `steps_text` | array | 否 | 手输步骤文本序列 |
| `grade_band` | enum | 否 | 未提供时由系统推断 |
| `client_request_id` | string | 是 | 幂等键，见 §8.1 |

### 3.2 响应

返回 [08](./08-diagnosis-result-schema.md) 定义的完整诊断结果；处理中时返回「处理中」状态与轮询句柄（长耗时场景）。

### 3.3 流式返回

端到端首屏时延目标靠分步返回保证（见 [07-performance-and-cost.md](./07-performance-and-cost.md) §2.1）。分四段推送：

| 段 | 内容 | 依赖 |
|---|---|---|
| 1 | 整题对错 + 错误步骤标红 | 判定完成 |
| 2 | 错误原因与知识点 | 归因完成 |
| 3 | 讲解与逆向解释 | 讲解生成完成 |
| 4 | 同类题 | P2 上线后启用 |

段 3 与段 4 允许降级为模板文案或省略（降级开关 G-2、G-5）。

## 4. IF-3/IF-4 批量批改与进度

### 4.1 提交

| 字段 | 说明 |
|---|---|
| `teacher_id` | 提交教师 |
| `classroom_id` | 目标班级 |
| `image_refs` | 作业照片引用列表 |
| `question_list_id` | 题目清单标识，用于重复题与漏题检测 |

### 4.2 进度

| 字段 | 说明 |
|---|---|
| `total` | 题量 |
| `completed` | 已完成题量 |
| `failed` | 失败题量 |
| `status` | `queued` / `running` / `partial_failed` / `done` |

### 4.3 续跑语义

批改过程中断（服务重启、超时、并发超限）时：

1. 已完成题目的结果保留，`completed` 计数不回退；
2. 支持从中断点续跑，续跑不重复消耗已完成的判定；
3. `status=partial_failed` 时，用户可选择重试失败题或接受部分结果；
4. 失败题必须可逐题查看失败原因。

这条语义在算法层没有对应物（[03](./03-alignment-and-diagnosis.md) §8 只定义单题退出码），是产品层必须补的一环。

## 6. IF-8/IF-10 反馈与纠正

用户侧入口的用户流程见 [11-interaction-flows.md](./11-interaction-flows.md) §6，本节只定义载荷。

| 接口 | 载荷要点 |
|---|---|
| IF-8 纠错反馈 | `result_id`、反馈类型（判错/原因不对/讲解看不懂）、用户描述、可选截图引用 |
| IF-10 步骤纠正 | `result_id`、被纠正的步骤 `index`、修正后的表达式 |

**IF-10 的副作用**：步骤纠正后触发重新诊断，生成新的 `result_id`，原结果保留并标记「已被纠正」（供 [04](./04-eval-set-and-annotation.md) §3.4 的难例集与 `01` §6.2 的回流使用）。

## 7. 统一错误码

错误码分两类，前缀区分。

### 7.1 业务错误码（对齐 `03` §8.1 退出码）

| 错误码 | 触发 | 用户可见话术来源 |
|---|---|---|
| `E-DAG-NO-PATH` | 无法到达目标表达式 | `03` §8.1 |
| `E-DAG-CYCLE` | 循环依赖 | 同上 |
| `E-DEPTH-EXCEEDED` | 展开深度超预算 | 同上 |
| `E-COST-EXCEEDED` | 节点数超预算 | 同上 |
| `E-ALIGN-FAILED` | 候选集合为空 | 同上 |
| `E-INVALID-EXPR` | 表达式无效 | `03` §8.4 |
| `E-GEOMETRY-NO-PARSE` | 图形未解析 | `03` §8.5 |
| `E-UNPARSABLE-INPUT` | 结构化三次失败 | `03` §8.6 |
| `E-OUT-OF-SCOPE` | 题型在覆盖矩阵外 | `02` §3.5 |

### 7.2 系统错误码

| 错误码 | 触发 | 重试建议 |
|---|---|---|
| `E-AUTH-DENIED` | 无权限 | 不重试 |
| `E-RATE-LIMITED` | 触发限流 | 延迟重试 |
| `E-DEPENDENCY-UNAVAILABLE` | 外部依赖不可用 | 延迟重试，见 [13](./13-resilience-and-maintainability.md) |
| `E-BUDGET-EXCEEDED` | 周期预算耗尽 | 次日重试或降级 |
| `E-INTERNAL` | 未分类内部错误 | 上报，不自动重试 |

**`E-OUT-OF-SCOPE` 必须携带题型族标识**，便于统计未被覆盖的题型分布，作为 `02` 覆盖矩阵的迭代输入。

## 8. 幂等、超时与重试

### 8.1 幂等

`client_request_id` 为幂等键。同一键重复提交返回首次结果，不重复消耗配额、不产生重复诊断记录。键的有效期建议覆盖一次会话（具体时长待选型后确定）。

### 8.2 超时

| 阶段 | 超时建议 |
|---|---|
| 诊断提交 | 按 [07](./07-performance-and-cost.md) §2 的端到端首屏目标设定 |
| 批量批改 | 分批执行，单批上限见 `07` §6.1 |
| 查询类 | 短超时，失败可安全重试 |

### 8.3 重试规则

| 错误类型 | 可否重试 | 说明 |
|---|---|---|
| `E-RATE-LIMITED` / `E-DEPENDENCY-UNAVAILABLE` | 可 | 需退避 |
| 业务错误码 | 否 | 重试无意义，应转退化模式或人工确认 |
| `E-INTERNAL` | 否 | 需上报 |

---

## 9. 字段级可见性

接口返回的字段须按 [06-identity-and-data-model.md](./06-identity-and-data-model.md) §3 的可见性矩阵裁剪，不依赖端侧过滤。两条硬约束：

1. **诊断快照字段不得出现在任何面向家长或教师的响应中**；
2. `traceability`、`cost`、`transforms` 属调试与复核字段，对学生端隐藏，仅学生本人查看诊断详情时可展示 `transforms`（家长与教师端不展示内部代价与代价阈值）。
