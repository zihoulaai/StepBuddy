# 03 诊断结果、班级报告与数据

## 本文档解决什么问题

批改完输出什么、班级层面看到什么、学生数据归谁管。三件事此前分散在多份文档里，且与已经删除的学生端/家长端耦合。本文档是教师场景下的唯一口径。

## 前置依赖与文档关系

判定与错误分类来自 `01` §4；知识点标识来自 `02`；指标口径与产能见 `04`。

## 1. 诊断结果结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 结果 schema 版本 |
| `result_id` | string | 唯一标识 |
| `versions` | object | IR schema、规则库、模型、模板四项版本 |
| `verdict` | enum | `correct` / `incorrect` / `partial` / `unknown` |
| `steps` | array | 逐步结果 |
| `source_error` | object | 源头错误，正确时为 null |
| `fallback` | object | 退化模式标记 |
| `teaching` | object | 正确路径、跳步补全、路径建议 |
| `knowledge_points` | array | 涉及的知识点。**MVP 阶段可为空**——知识点体系在完整版开发前定义，MVP 只验证建模与判定，不做知识点聚合 |

四项版本是争议复核与结果复现的依据，缺任一项该结果不可用于复核。

### 1.1 逐步结果

| 字段 | 说明 |
|---|---|
| `index` | 与步骤 IR 对齐 |
| `status` | `correct` / `incorrect` / `inherited` / `not_judged` |
| `equivalence_level` | 严格 / 形式 / 近似 |
| `cost` | 该步对齐代价 |
| `transforms` | 命中的元规则，规则引擎写入 |
| `error` | 错误明细 |

`status` 与错误类型的对应：源头错误与并发次要错误都是 `incorrect`，由 `error.role` 区分；继承错误为 `inherited`；未通过不变量检查或触发退化模式为 `not_judged`，不计入准确率分母。

### 1.2 错误明细

| 字段 | 说明 |
|---|---|
| `role` | `source` / `concurrent` / `inherited` |
| `classification` | `knowledge` / `behavioral` / `normative` |
| `subtype` | 行为性下位：`slip`（笔误）/ `miscalc`（计算失误） |
| `rule_id` | 规则级定位 |
| `location` | 位置级定位（出错片段与提示） |
| `reason` | 面向教师的原因 |
| `traceable` | 该原因能否追溯到 `transforms` |

**`traceable` 为 false 的原因不得出现在错误原因区**，只能出现在建议区。归因可追溯率（目标 100%）以此统计。

### 1.3 退化标记

| 字段 | 说明 |
|---|---|
| `mode` | `answer_only` / `multi_solution` / `invalid_expr` / `geometry_no_parse` 等 |
| `exit_code` | 见 `01` §5 |
| `user_message` | 教师可见话术 |
| `partial_steps` | 已判定步骤数 |

## 2. 班级报告

班级报告取代此前设计的个人掌握度模型。学生无账号，不做个人长期模型（无时间衰减、无连对连错、无个人证据累积）。统计维度是班级与知识点。

| 字段 | 说明 |
|---|---|
| 参与人数 | 有有效批改结果的学生数 |
| 逐题正确率 | 每道题的正确人数占比 |
| 知识点正确率 | 按知识点聚合的正确率 |
| 错误分类分布 | 知识性 / 行为性 / 规范性的占比 |
| 共性薄弱点 | 班级正确率 <40% 的知识点，按升序排 |
| 高频错误步骤 | 按错误模式聚合的 Top10 |
| 数据充分性 | 样本不足时标注，不做趋势判断 |

**不做的事**：不生成学生排名，不生成班级间对比，不做个人长期掌握度。班级报告只回答「全班哪些知识点有问题」，供教师决定讲什么。

聚合方式：批改完成后增量计算，不做全量重算；延迟目标待部署形态确定后回填；聚合失败不影响单题结果。

## 3. 数据模型

| 实体 | 说明 |
|---|---|
| 教师 | 账号由学校管理员开通，授权到班级，授权有有效期 |
| 班级 | 教师的作用范围，含班级名单 |
| 班级名单条目 | 学生姓名或编号，学生**无独立账号** |
| 作业批次 | 一次批改任务，关联班级，含状态 |
| 扫描记录 | 一份学生作业的扫描结果，含影像引用、切题结果、归属、状态 |
| 批改记录 | 逐题结果，关联扫描记录 |
| 诊断快照 | 完整输入输出留存，用于争议复核，保留 12 个月 |

**作业批次状态**：`scanning`（扫描中）→ `ready`（全部扫描完成待诊断）→ `diagnosing`（诊断中）→ `done`（完成）→ `partial_failed`（部分失败）。

**扫描记录状态**：`scanned`（已扫描待确认）→ `confirmed`（已确认）→ `excluded`（教师排除，不参与诊断）。只有 `confirmed` 的份进入诊断段。

**扫描与诊断解耦的存储含义**：扫描段产生的扫描记录不依赖诊断结果，可独立保存与修改；诊断段以已确认的扫描记录为输入，不回写扫描记录。教师修改某份归属后，若该批已诊断，需重新触发诊断并生成新记录，不覆盖原结果。

### 3.1 归属与身份

教师维护班级名单（姓名或编号）。逐份扫描时按名单顺序预填归属，教师确认或手动改，**不做姓名识别**。一份作业含多人时标为异常，建议重扫为单人单份。无名单时按序号标注并在报告中注明。

### 3.2 可见性

| 数据 | 教师 | 学校管理员 | 其他教师 |
|---|---|---|---|
| 本班作业与批改结果 | 可读 | 可读 | 不可见 |
| 其他班级数据 | 不可见 | 可读 | 不可见 |
| 诊断快照 | 可读（用于复核） | 可读 | 不可见 |
| 规则库与错误模式 | 只读 | 可维护 | 只读 |

按行列逐格判定，不做角色整体授权。

### 3.3 合规

条款见 PRD 六章 C-1 至 C-8，要点：学校作为委托方签署数据处理约定；训练用途默认关闭；学校可撤回授权并要求删除；作业照片留存 ≤24 个月、批改记录 ≤36 个月；传给模型服务的内容仅限表达式与步骤文本，不含姓名、学校、班级、照片。

**删除联动**：学校请求删除时，备份副本必须同步清除，否则删除在法律意义上未完成。

## 4. 接口摘要

扫描段与诊断段是两组独立接口。

| 编号 | 接口 | 要点 |
|---|---|---|
| IF-1 | 创建作业批次 | 班级标识、题目清单标识（可选） |
| IF-2 | 提交一份扫描 | 影像引用、顺序号、幂等键；返回切题结果与预填归属 |
| IF-3 | 确认或修改一份扫描 | 确认归属、可指定学生、可标记为排除 |
| IF-4 | 开始诊断 | 批次标识；存在未确认份时拒绝并提示 |
| IF-5 | 查询诊断进度 | 总量、已完成、失败、批次状态 |
| IF-6 | 查询批改结果 | 逐题结果，按知识点或学生筛选 |
| IF-7 | 查询班级报告与导出 | 报告字段见 §2；导出格式待定 |

错误码分两类：

| 类别 | 示例 | 说明 |
|---|---|---|
| 业务 | `E-DAG-NO-PATH`、`E-ALIGN-FAILED`、`E-INVALID-EXPR`、`E-GEOMETRY-NO-PARSE`、`E-OUT-OF-SCOPE` | 对齐 `01` §5 退出码；`E-OUT-OF-SCOPE` 须携带题型族标识 |
| 系统 | `E-AUTH-DENIED`、`E-RATE-LIMITED`、`E-DEPENDENCY-UNAVAILABLE`、`E-BUDGET-EXCEEDED` | 可否重试见下表 |

重试规则：限流与依赖不可用可退避重试；业务错误码不重试，转退化模式或人工核对；内部错误上报不自动重试。
