# 01 批改流程与诊断算法

## 本文档解决什么问题

教师批改场景下，主链路不是诊断，而是**把一叠作业照片变成结构化的、归属到人的逐题作答**。切错一道、归错一人，后面诊断再准也没用。本文档定义这条主链路，以及其后的诊断算法。

## 前置依赖与文档关系

题型范围见 `02`；结果结构与班级报告见 `03`；指标口径与产能见 `04`；术语见 PRD 附录 A。

## 1. 批改主流程

全流程分两段，扫描段与诊断段解耦。**不支持一次上传多张照片**，教师逐份扫描。

### 1.1 扫描段（逐份进行）

| 步 | 内容 | 失败处理 |
|---|---|---|
| 1 | 扫描一份作业（单页或多页同一人的作业） | 影像不清晰可当场重扫，不产生记录 |
| 2 | 切题：把这份作业切成多道题 | 切分不确定的区域标出，教师当场调整 |
| 3 | 归属：按名单顺序预填，教师确认或手动改 | 无法确定的标为「待确认」 |
| 4 | 教师确认该份 | **未确认的份不计入后续诊断** |
| 5 | 继续下一份，直到全部扫完 | 可随时中断，已扫份保留 |

### 1.2 诊断段（全部扫描完成后统一进行）

| 步 | 内容 | 失败处理 |
|---|---|---|
| 1 | 教师点击「开始诊断」 | 有未确认份时提示先完成确认 |
| 2 | 逐题批改与步骤级诊断 | 单题失败不影响其他题，可重试 |
| 3 | 汇总为班级结果 | — |

**为什么要解耦**：扫描时不等待诊断，一份没扫好可以当场重扫；诊断可以批量处理，教师不必守着；切题与归属的问题在扫描段就修掉，不会带进诊断段污染结果。

**确认不可跳过**。系统的归属结果只是建议，教师确认后才成为事实。

## 2. 输入处理

### 2.1 切题

| 项 | 要求 |
|---|---|
| 输入 | 一份作业（单人或单本），可含多页；单页可含多题 |
| 输出 | 题目区域列表，含题目文本、作答区域、题号（若有） |
| 题号对齐 | 若教师提供题目清单，按题号映射；无清单时按序号标注 |
| 失败 | 切分不确定的区域当场标出，教师可在界面上调整边界或重扫 |

### 2.2 归属

逐份扫描让归属变得确定：**教师按班级名单顺序扫，系统按顺序预填归属，教师只需确认或手动改**。不需要姓名识别，因此也没有识别错误。

| 项 | 要求 |
|---|---|
| 依据 | 扫描顺序对应名单顺序；教师可手动改任一份的归属 |
| 预填规则 | 第 N 份预填为名单中第 N 个未扫到的学生 |
| 输出 | 每份的归属结果 |
| 顺序错乱处理 | 教师手动指定该份的学生；已扫份可重新指定 |
| 混排处理 | 一份作业含多人时标为异常，建议重扫为单人单份 |

顺序预填的准确率取决于教师是否按序扫描。教师不按序时由手动指定兜底，因此归属准确率阈值（≥98%）仍成立——错误只可能来自教师的误操作，而这由确认环节拦截。

### 2.3 切分与归属准确率定义

| 指标 | 定义式 | P0 阈值 |
|---|---|---|
| 切分准确率 | 边界完全正确的题目数 / 实际题目总数 | ≥95% |
| 归属准确率 | 归属正确的份数 / 已确认份数 | ≥98% |

分母只计教师确认过的对象：切分按题计，归属按份计——逐份扫描下归属的单位是一个学生的整份作业。切分错误导致的题目丢失按错误计，不按缺失剔除——丢一道题就是错一道。

### 2.4 拍照纠偏

识别不确定时不按置信度直接改数值，而是生成候选值集合，用「假设该候选值成立时后续步骤是否全部自洽」择一。择一依据与置信度一并记录。无择一依据时标红由教师确认，系统不替教师决定。

### 2.5 与笔误判定的优先级

拍照纠偏与笔误判定都使用「后续链路自洽」，同时成立时**先判识别修正、后判笔误**。原因归属不同：前者错在系统看错，后者错在学生写错。

## 3. IR 契约

### 3.1 题目结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 版本号 |
| `question_type` | enum | 见 `02` §1 |
| `grade_band` | enum | G1–G6 |
| `entity` | object | 已知量、未知量、单位、量纲 |
| `relation` | array | 数量关系；纯计算题可为空 |
| `target` | object | 求解目标与结果形式 |
| `constraint` | object | 简便运算、保留小数、最简分数等要求 |
| `tags` | object | 知识点与规则标签，**只能由规则引擎写入** |

### 3.2 步骤结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `index` | integer | 从 1 连续递增 |
| `raw_text` | string | 学生原始书写 |
| `expr_before` / `expr_after` | string | 规范化后的表达式 |
| `split_checked` | boolean | 是否通过原子步不变量检查 |
| `source` | enum | `photo` / `manual` |
| `answer_only` | boolean | 是否只写答案未写过程 |

### 3.3 表达式 DSL

```ebnf
Expr     ::= Term (('+' | '-') Term)*
Term     ::= Factor (('×' | '÷') Factor)*
Factor   ::= Unary ('^' Unary)?
Unary    ::= ('-')? Postfix
Postfix  ::= Primary Unit?
Primary  ::= Number | Fraction | Percent | '(' Expr ')' | Ident
Number   ::= Digit+ ('.' Digit+)?
Fraction ::= Digit+ '/' Digit+
Percent  ::= Number '%'
```

约束：

- 数值以精确有理数表示，等价判定不经过浮点中间态；
- 不允许隐式乘法，`1/2 2/3` 判为非法而非补乘号；
- 除数为 0 的表达式进入无效状态，不参与等价判定；
- 单位参与判定，`5厘米/厘米` 与 `5` 不等价。

### 3.4 原子步不变量检查

一步一变换、量守恒、单位一致、变量集合单调。未通过的步骤标记 `split_checked=false`，按多变换处理且不参与等价判定。

### 3.5 示例

```json
{
  "schema_version": "1.0.0",
  "question_type": "fraction_arith",
  "grade_band": "G5",
  "entity": {
    "entities": [
      { "id": "n1", "role": "known", "name": "被乘数", "value": { "num": 1, "den": 2 } },
      { "id": "n2", "role": "known", "name": "乘数", "value": { "num": 2, "den": 3 } },
      { "id": "n3", "role": "known", "name": "被加项", "value": { "num": 3, "den": 4 } }
    ]
  },
  "target": { "type": "value", "answer_form": "fraction" },
  "constraint": { "require_simplest_form": true },
  "steps": [
    {
      "index": 1,
      "raw_text": "1/2 x 2/3 = 2/3",
      "expr_before": "1/2 * 2/3",
      "expr_after": "2/3",
      "split_checked": true,
      "source": "photo",
      "answer_only": false
    },
    {
      "index": 2,
      "raw_text": "3/4 + 2/3 = 9/12 + 8/12 = 17/12",
      "expr_before": "3/4 + 2/3",
      "expr_after": "17/12",
      "split_checked": false,
      "source": "photo",
      "answer_only": false
    }
  ]
}
```

第 1 步把 `1/2 * 2/3` 算成 `2/3`（只乘了一个因数），是本题的源头错误；第 2 步含两次变换且未通过不变量检查。

## 4. 诊断算法

### 4.0 两条判定路径

不是所有题都需要同等重量的机制。

| 路径 | 适用 | 判定流程 |
|---|---|---|
| **完整机制** | 应用题 | 关系层四角色建模 → 解题空间生成 → 步骤对齐 → 前向溯源 → 错误分类与定位 |
| **轻量判定** | 计算类（整数、小数、分数、列式、解方程） | 解析学生步骤 → 逐步用精确计算校验等价 → 定位首个不等价步 → 错误分类 |

**为什么分两条**。计算类的数学是确定的：学生写 `3/4 + 1/2 = 5/4`，校验只需确认每一步的等价性，不需要先生成一棵所有可能解法的树。生成完整解题空间对这类题是浪费。

应用题不同：难点在自然语言转结构化关系。学生把「甲比乙多 10 个」写成 `x + (x + 10)` 还是 `x + (x - 10)`，这不是计算错误，是建模错误——只有先建立关系层、再走对齐与溯源才能定位。**这也是本产品的核心价值所在。**

两条路径共用同一套结果结构（`03` §1）与错误分类（§4.4），差别只在中间是否生成解题空间。判定仍全部由规则与精确计算完成，模型不参与对错判定。

### 4.1 前向溯源

源头错误是**第一个**导致后续偏离的步骤，必须从前向后确定。从后往前扫命中的必然是最后一步，不是源头。

| 步骤 | 内容 |
|---|---|
| 规范化 | 统一等价写法（单位、尾随零、百分数、运算符）后再比对 |
| 投影 | 把学生步骤序列投影到解题空间，为每步找候选节点 |
| 前向对齐 | 从第 1 步起，取最小代价节点作为匹配 |
| 判定 | 首个代价超阈值的步为源头错误 |
| 继承标记 | 源头错误之后、由其错误结果推导的步标为继承错误，不重复扣分 |

**合法但非推荐路径一律判对**。学生先约分后通分，而推荐路径是先通分后约分，两者都合法，判对并给出路径建议。只有当某一步在**全部合法路径下都无法匹配**时才判错。

### 4.2 代价与阈值

$$C(s,n) = 0.15 \cdot D_{str} + 0.35 \cdot D_{edit} + 0.40 \cdot D_{eq} + D_{skip} + D_{beyond}$$

| 代价区间 | 判定 |
|---|---|
| ≤0.15 | 完全匹配，判对 |
| 0.15–0.25 | 可接受变体，判对并给路径建议（阈值 τ = 0.25） |
| 0.25–0.40 | 可疑，先查识别修正与链路自洽，不直接判错 |
| >0.40 | 判错，进入错误分类 |

阈值须由评测集校准后才可上线。

### 4.3 等价判定

容差量化：要求保留 N 位小数时绝对偏差 ≤ `0.5×10^(-N)`；要求估算时 ≤0.5；无精度要求时不启用近似等价。

不判错的差异：`0.5` 与 `1/2`、带分数与假分数、单位前置后置、未约分到最简（给提示）。判错的差异：缺单位（题目要求时）、未按要求保留精度。

### 4.4 错误分类与定位

| 分类 | 子类 |
|---|---|
| 知识性 | 概念误解、规则误用、公式记错 |
| 行为性 | 笔误、计算失误 |
| 规范性 | 格式错误、漏写单位、没写答句 |

反馈优先级为知识性 > 行为性 > 规范性，这是反馈次序，不代表严重程度递进。

**规则级定位只能由规则引擎逆向推导**——取该步前后表达式的最小合法元规则集合。模型若产出规则标签，一律降级为辅助字段，权重为 0，不参与归因。不存在可解释的元规则集合时，错误原因只能表述为「无法用已支持规则解释该步」，不得让模型补一个理由。

**应用题的建模错误**归属知识性，定位在关系层：指明是哪一个关系（主体、基准量、比较量、运算关系）写反了，而不是指出哪一步计算出错。

### 4.5 笔误判定

三项同时满足才判笔误：

| 条件 | 内容 |
|---|---|
| B-1 | 该步为誊写型步骤，不含关系建模 |
| B-2 | 差异落在已知易混淆字符对内，或单字符编辑距离 ≤1，且数值相对偏差 ≤50% |
| B-3 | 该步之后所有步骤在「假设该步取标准值」时全部可对齐 |

附加：同题内同类笔误出现两次及以上，升级为知识性错误。

### 4.6 跳步

学生把多次变换写进一步时，若可被合法元规则补全，输出补全路径并标出关键步；补全失败则按多变换逐个对齐。跳步不再只是「不判错」，而是转为可操作的反馈。

## 5. 退化模式与退出码

| 退出码 | 触发 | 教师可见行为 | 可继续 |
|---|---|---|---|
| `ANSWER_ONLY` | 学生只写答案未写过程 | 只给对错，不给原因，提示该题无法步骤诊断 | 是 |
| `DAG_NO_PATH` | 无法生成解题空间 | 「该题暂无标准解过程」 | 否 |
| `DEPTH_EXCEEDED` | 步骤超限 | 「步骤较多，已按前 N 步诊断」 | 是（部分结果） |
| `COST_EXCEEDED` | 节点数超预算 | 同上 | 是（部分结果） |
| `ALIGN_FAILED` | 某步无法匹配 | 标出该步，提示人工核对 | 核对后可 |
| `INVALID_EXPR` | 算式本身写错 | 「算式本身写错，请检查除数是否为零」 | 否 |
| `GEOMETRY_NO_PARSE` | 图形未识别 | 「图形部分未识别，相关步骤未校验」 | 是（部分结果） |
| `UNPARSABLE_INPUT` | 识别三次仍失败 | 转人工输入，保留原图对照 | 是 |

应用题另有专属退出码：`MODEL_FAILED`（关系无法建模），教师可见行为为「该题题意无法解析，建议人工批改」，不计入建模失败以外的指标。

部分结果必须明确告知「未覆盖的部分未校验」，不得让教师误以为整题已批改。

## 6. 教师端交互

**扫描段**

| 环节 | 成功 | 失败 | 中断 |
|---|---|---|---|
| 扫描一份 | 显示切题结果与预填归属 | 提示重扫 | 不产生记录 |
| 调整与确认 | 该份标记已确认，进入下一份 | 标出不确定区域 | 已扫份保留，可随时继续 |
| 全部扫完 | 提示「可以开始诊断」 | — | 已扫份保留 |

**诊断段**

| 环节 | 成功 | 失败 | 中断 |
|---|---|---|---|
| 开始诊断 | 展示进度 | 有未确认份时提示先确认 | — |
| 逐题批改 | 进度递增 | 单题失败可重试 | 已完成结果保留，支持续跑 |
| 查看与导出 | 展示班级结果 | — | — |

**续跑**：诊断中断后已完成结果保留，支持从中断点继续，失败题可逐题重试或批量重试。扫描段不受影响，已确认的份不会被重置。

**界面四态**：加载、空、错误、数据过期。数据过期指结果基于旧规则库版本，需提示可重新批改，重新批改产生新记录不覆盖原结果。

## 7. 验收清单

- [ ] 流程分扫描段与诊断段，两段解耦且不支持多张照片一次上传
- [ ] 扫描段五步各有成功、失败、中断三态
- [ ] 归属按名单顺序预填，教师可手动改，不需要姓名识别
- [ ] 归属确认不可跳过，未确认不计入诊断与统计
- [ ] 两条判定路径的适用题型与流程差异成文
- [ ] IR 字段表、DSL 文法、示例齐全，规则标签归属明确
- [ ] 前向溯源、代价阈值、容差、笔误三条件、跳步处理成文
- [ ] 应用题建模错误的分类与定位方式成文
- [ ] 九类退出码各有教师可见行为与可否继续
- [ ] 部分结果必须告知未覆盖部分
- [ ] 续跑语义成文
