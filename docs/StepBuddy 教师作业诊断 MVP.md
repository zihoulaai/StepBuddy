# 教师作业诊断 MVP

> **版本**：v1.0（定稿）｜**日期**：2026-10-02｜**配套**：`docs/StepBuddy 教师作业诊断系统 PRD.md` v1.0

## 这是什么

验证**应用题的建模与诊断机制是否可行**的最小实验。只做应用题，不引入其他复杂度。

MVP 不是产品的第一版，是方案的验证。完整产品定义见 `docs/StepBuddy 教师作业诊断系统 PRD.md`。

## 为什么只做应用题

计算类题型（整数、小数、分数、列式、解方程）在数学上是确定的，用规则加精确计算就能判定，不需要复杂机制——做它们验证不了任何有难度的问题。

应用题才是核心：它由自然语言描述，「甲比乙多 10 个」到底写成 `x + (x - 10)` 还是 `x + (x + 10)`，这不是计算问题，是**自然语言到结构化关系的转换问题**。这一步走不通，整个产品不成立。

所以 MVP 只验证这一件事。

## 验证的核心假设

> 自然语言描述的应用题，能被转成结构化的数量关系，并据此准确定位学生的错误步骤与错误原因。

拆成三个可测的点：

| 编号 | 假设 | 验证方式 |
|---|---|---|
| A-1 | 题干能被正确建模为结构化关系 | 建模成功率 |
| A-2 | 学生步骤的错误位置能被准确定位 | 步骤级判定准确率 |
| A-3 | 错误原因能被正确归因 | 归因准确率 |

## MVP 范围

| 项 | 范围 |
|---|---|
| 题型 | 应用题两族：和差、和倍、差倍、归总；归一、归总 |
| 输入 | **文本输入**：题目文本 + 学生步骤文本 |
| 机制 | 关系层四角色建模 → 解题空间生成 → 步骤对齐 → 前向溯源 → 错误分类与定位 |
| 输出 | 对错、错误步骤、错误分类与原因、正确路径 |

### 为什么用文本输入

扫描、切题、归属这些环节是工程复杂度，不是机制风险。用文本输入可以把它们全部绕开，让 MVP 只面对真正的问题：自然语言能不能转成结构化关系。

这些环节在完整版中定义完备（`01` §1–§2），MVP 只是不实现。

## 明确不做

扫描与影像处理、切题、学生归属、班级与名单管理、作业管理、导出打印、班级报告、教师改判界面、其余所有题型、账号与权限、后台配置、多模型交叉验证、金标集。

**不做不等于不设计**：数据结构按完整版预留（`01` §3 的 IR 契约、`03` §1 的结果结构），避免完整版开发时返工。

## 验证方式

不用产品试用，用评测集。

| 步 | 内容 |
|---|---|
| 1 | 构建评测集：150 道应用题，覆盖两族，含正确解法与各类错误解法（建模错误、计算错误、规范性错误） |
| 2 | 人工标注每道题的建模结果、逐步对错、错误分类 |
| 3 | 系统跑评测集，逐项对比人工标注 |
| 4 | 统计三项指标，分析失败案例 |

错误解法占比不低于 40%——只测正确解法无法验证「学生写错时能否正确归因」。

## 验收标准

| 指标 | 阈值 | 说明 |
|---|---|---|
| 建模成功率 | ≥80% | 无法建模的题不超过 20%；失败的题有明确的 `MODEL_FAILED` 退出码，不静默错判 |
| 步骤级判定准确率 | ≥90% | 见 `04` §1 的 M-1 定义 |
| 归因准确率 | ≥85% | 见 `04` §1 的 M-2 定义 |
| 关系角色准确率 | ≥92% | 四角色全对的比例，这是应用题特有的关键指标 |

口径标签为 `AI 自评·内部口径`（标注由模型辅助完成，人工抽样复核）。

## 工期

约 **6 周**。

| 周 | 任务 | 交付物 |
|---|---|---|
| 1 | IR 契约与表达式 DSL | 数据结构、解析器 |
| 2–3 | **应用题建模规则（`REL.MODEL` 两族）**与验收用例 | 规则库 v0.1 |
| 3 | **检查点**：两族建模规则完成 | — |
| 4 | 关系层校验、解题空间生成、步骤对齐、前向溯源、错误分类 | 诊断引擎 |
| 5 | 结果输出；评测集构建与标注 | 结果结构、评测集 |
| 6 | 抽样复核、失败案例分析、修复与验收 | 验收报告 |

第 3 周设检查点：建模规则是风险最高的部分，走不通要尽早发现。

## 交付后的决策

| 情况 | 决策 |
|---|---|
| 三项指标全部达标 | 方案可行，进入完整版开发：补扫描与归属、班级管理、其余题型、报告与导出 |
| 建模成功率不达标 | **最高优先**：核心机制不成立，重做 `REL.MODEL`，不进下一步 |
| 建模达标但判定不达标 | 问题在对齐或溯源环节，针对性修，不必重做建模 |
| 判定达标但归因不达标 | 问题在错误分类规则，单独修 |

**只按这三项指标决策**。MVP 阶段不做教师试用、不做性能验证、不做合规验证——这些都是完整版的事。MVP 的唯一任务是回答「应用题这条路走不走得通」。
